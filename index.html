Phase 0 · How code runs

      
01
You write plain text
Source code is just a text file — hello.py, Main.java, main.rs. The computer can't run text. Something has to translate it.
The highlighted column is the path for your selected language.

      
02
A translator reads it
A compiler translates the whole program ahead of time. An interpreter translates as it runs. This step is where syntax errors are caught.

      
03
It becomes instructions
Native languages (C, C++, Go, Rust) produce a machine-code executable. Java and C# produce portable bytecode. Python and JavaScript make bytecode in memory, on the fly.

      
04
The CPU executes
Native code runs straight on the CPU. Bytecode runs on a virtual machine (JVM, .NET CLR, CPython, V8) that often JIT-compiles hot code into machine code while running. This is why setup differs per language: you're installing a compiler, a VM, or an interpreter.

Phase 1 · Before you install anything

    
The terminal & PATH, demystified

    
Every setup guide says "run this in your terminal" and "add it to PATH". Here is what those actually mean — 90% of beginner setup problems are PATH problems.

    

      

        
What is the terminal?

        
A text window where you type commands to a program called a shell (PowerShell on Windows, zsh on macOS, bash on Linux). The shell is always "standing in" a folder — the current working directory. Commands run relative to it.

        
Open it: Windows → press Win, type "Terminal". macOS → ⌘ Space, type "Terminal". Linux → Ctrl Alt T.

      

      

        
The 6 commands you need

        

          
CommandWhat it does

          
pwdPrint where you are

          
lsList files here (dir in old cmd.exe)

          
cd folderMove into a folder; cd .. goes up

          
mkdir nameMake a folder

          
code .Open this folder in VS Code

          
↑ / TabPrevious command / autocomplete names

        

      

    

    
    
💡
The golden rule: after installing anything, close and reopen your terminal. A terminal reads PATH once when it starts, so a freshly installed tool is invisible to windows that were already open. On Windows, also consider WSL (wsl --install) to get a real Linux environment — many tutorials assume it.
